# Portable Creative Logic

## Purpose

Turn prior Hottop learning into **portable creative mechanisms** that can transfer across products, categories and campaigns.

This skill exists to prevent two failure modes:

1. treating every past success as a brand-specific trick;
2. reusing an old visual shell, character or four-panel template just because it worked before.

The reusable unit is:

`hotspot signal -> audience hook -> causal mechanism -> product role -> visible consequence -> platform-native packaging`

Canonical sources:

- `integrations/portable-creative-logic-library.yml`
- `docs/creative/portable-creative-logic-taxonomy.md`
- `docs/research/2026-09-01-portable-creative-hook-evidence.md`

This library complements, not replaces, `creative-reference-memory`. The reference library stores concrete positive/negative cases and feedback. This portable library stores generalized hook families, search keywords, hotspot domains and product-role mappings.

## Mandatory order

For every fresh image/video/social creative run:

1. recover `PROJECT.md` and `STATUS.md`;
2. resolve the currently promoted product/subject from current facts;
3. analyze the supplied hotspot, or perform fresh live hotspot discovery;
4. separate source event from active derivative meme/question/action;
5. **then** retrieve portable logic candidates from this library;
6. retrieve concrete creative-reference memory when useful;
7. map the selected mechanism to a real current product capability;
8. choose format/medium from the current hotspot and product bridge;
9. run normal review, safety and generation preflight.

Never use the portable library to skip fresh hotspot research.

## Retrieval query

Build a small query object from the current request:

- `hotspot_domain`: finance_markets / technology_ai / workplace / sports / entertainment_culture / consumer / policy_society / internet_meme / business_sales / creator_design;
- `hotspot_signals`: exact current words, numbers, actions, questions and reactions people are using;
- `audience_intent`: understand / decide / save time / avoid mistake / be entertained / share / compare / act;
- `product_job`: what the promoted subject can actually do;
- `candidate_product_roles`: researcher / analyst / verifier / executor / organizer / reviewer / creator / planner / scout / matcher / monitor / etc.;
- `platform`;
- `risk_flags`.

Expand the query with `search_query_expansion` only as search vocabulary. Do not put internal taxonomy words on the final creative surface.

## Candidate selection

Retrieve 3–7 hook families. Rank with the library default score:

- hotspot-native fit: 25
- product-role fit: 25
- instant comprehension: 15
- surprise/reframe: 15
- platform fit: 10
- ownability: 10

Reject any candidate if:

- the product can be swapped with almost any unrelated brand without changing the outcome;
- the hook requires a false factual claim;
- it depends on a protected character/likeness/brand surface rather than a mechanism;
- it is merely an old Hottop image with nouns replaced;
- the headline is brand-first while the cold audience has no reason to care yet;
- the product role overclaims what the product can actually do.

## Product migration rule

When the promoted product changes, **re-run product-role mapping**. Never just replace the brand name.

Example: `hotspot_question_product_work`

- research/finance product -> gather sources, compare assumptions, produce a memo;
- sales-intelligence product -> find real buyers/sellers/demand signals behind the question;
- knowledge product -> organize sources and decision context;
- automation product -> execute the workflow triggered by the question;
- creative product -> turn the question into an asset/story/output;
- coding product -> implement/test the task implied by the hotspot;
- collaboration product -> coordinate roles, revisions and handoffs.

The hook family can remain similar while the causal product role changes completely.

## High-value families

The YAML is authoritative. Frequently useful families include:

- `open_question` — “到底/为什么/值多少” information gap;
- `specific_number` — concrete scale/consequence;
- `concrete_consequence` — outcome first;
- `not_x_but_y` — reframe;
- `role_reversal` — change who does the work;
- `unexpected_reversal` — coherent surprise;
- `constraint_deletion` — remove the old step instead of optimizing it;
- `hotspot_question_product_work` — live public question -> product performs the real work;
- `hotspot_action_product_action` — borrow the hotspot action verb -> product takes the analogous action;
- `comment_phrase_remix` — current derivative-meme wording instead of newsroom summary;
- `proof_demo` — show task/output instead of listing features;
- `practical_value` — save-worthy/how-to packaging;
- `one_sentence_compression` — compress complex value into a memorable line.

## Platform routing

Platform rules are priors, not laws. Actual account performance overrides generic advice when enough comparable data exists.

- Douyin/TikTok: hook immediately; concrete conflict/outcome; native vertical/text/sound; avoid brand-name-first cold opens.
- Xiaohongshu: practical value, experience, comparison, save-worthy first image; avoid product-announcement-only framing.
- WeChat Channels: event relevance, clear consequence, shareable context.
- Kuaishou: direct benefit, plain language, visible proof.
- Weibo: current phrase/question/number/reaction; derivative meme first.
- YouTube: accurate intrigue, succinct title, readable thumbnail, immediate delivery on the title promise.

## Learning protocol

After a creative run with meaningful user feedback or platform performance:

1. store concrete case evidence in `creative-reference-library.yml` when appropriate;
2. update `portable-creative-logic-library.yml` only when the lesson is genuinely product-independent;
3. distinguish:
   - `account_specific_observation`,
   - `platform_official_guidance`,
   - `academic_or_industry_evidence`,
   - `project_hypothesis`;
4. never turn one account's result into a universal rule;
5. archive the selected logic IDs with the creative record so later performance can be attributed to a mechanism.

## Financial and real-person guardrails

Finance/market hooks may use current public questions, market moves and research workflows, but:

- do not fabricate valuation conclusions, target prices or certainty;
- distinguish facts, estimates, opinions and scenarios;
- do not give personalized investment instructions in promotional creative;
- use current cited data for numerical claims.

For public figures/athletes/entrepreneurs:

- borrow the current event or role mechanism;
- do not generate a promotional likeness or protected character surface by default;
- prefer original archetypes unless rights-cleared material exists.

## Core rule

**Persist mechanisms, not mascots. Persist product roles, not product names. Persist search language, not yesterday's headline.**
