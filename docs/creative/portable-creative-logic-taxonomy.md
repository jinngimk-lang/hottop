# Portable Creative Logic Taxonomy

## Why this exists

Hottop should learn **transferable creative logic**, not memorize one product, one mascot, one headline or one successful image.

A reusable creative unit is:

`current hotspot -> native hook -> causal mechanism -> current product role -> visible outcome -> platform-native packaging`

Examples are evidence. They are not templates.

The machine-readable source is:

- `integrations/portable-creative-logic-library.yml`

The invocation protocol is:

- `skills/portable-creative-logic/SKILL.md`

Research evidence is:

- `docs/research/2026-09-01-portable-creative-hook-evidence.md`

## Retrieval dimensions

Every new creative should be described across these dimensions:

| Dimension | Question |
| --- | --- |
| Hook family | What makes a cold viewer stop: question, number, reversal, utility, conflict, emotion? |
| Hotspot domain | Finance, AI/tech, workplace, sports, entertainment, consumer, policy, meme, sales, creator? |
| Hotspot signal | What exact phrase, number, action or object is currently repeated by users? |
| Audience intent | Understand, decide, compare, avoid mistakes, save time, laugh, share, act? |
| Product job | What can the product truthfully do now? |
| Product role | Researcher, executor, verifier, organizer, creator, scout, etc.? |
| Platform | What packaging does the distribution surface reward for this account? |
| Risk | Finance claims, real-person likeness, trademark, copyright, sensitive event, unsupported comparison? |

## Product-role library

A hook should not determine the product role. The product capability determines the role.

### Research / decision products

Roles:

- `researcher`
- `analyst`
- `verifier`
- `forecaster`
- `summarizer`
- `challenger`

Good bridges:

- public question -> evidence work;
- controversy -> assumptions and source comparison;
- complex report -> decision memo;
- market move -> drivers/scenarios rather than a fake prediction.

### Automation / agent products

Roles:

- `executor`
- `operator`
- `automator`
- `coordinator`
- `planner`
- `breaker`

Good bridges:

- repeated pain -> hand the task over;
- old workflow -> delete the step;
- hotspot action -> product takes the analogous action;
- deadline -> product executes while human decides.

### Collaboration / knowledge products

Roles:

- `organizer`
- `reviewer`
- `coordinator`
- `summarizer`
- `navigator`
- `cleaner`

Good bridges:

- information chaos -> single decision context;
- repeated revisions -> controlled review;
- scattered sources -> structured workspace;
- “where is the final version?” -> lineage/context, not another chat window.

### Sales / market-intelligence products

Roles:

- `scout`
- `matcher`
- `researcher`
- `monitor`
- `verifier`

Good bridges:

- everyone talks about a market -> find real buyers/sellers;
- “who needs this?” -> discover demand signals;
- hot industry -> identify concrete procurement/recruiting/partnership intent;
- news event -> monitor follow-on commercial signals.

### Creative / design / media products

Roles:

- `creator`
- `generator`
- `reviewer`
- `operator`

Good bridges:

- everyone discusses the hotspot -> produce the asset;
- challenge/test -> generate under a clear constraint;
- comment phrase -> native visual execution;
- before/after -> visible artifact transformation.

### Coding / developer products

Roles:

- `coder`
- `executor`
- `reviewer`
- `breaker`
- `operator`

Good bridges:

- technical launch -> implement, test, debug;
- “can it really do X?” -> falsifiable task;
- deployment/tooling pain -> constraint deletion;
- incident -> reproduce/check/fix rather than generic AI chat.

## Platform routing

These are priors. Current account data should update them.

### Douyin / TikTok

Prefer immediate conflict, question/number/consequence, human face/action, first-seconds payoff, native text/sound. Avoid brand name as the only cold hook, feature lists before the problem, and slow context.

### Xiaohongshu

Prefer practical value, useful comparison, experience, checklists/templates, first image carrying the core promise, and save-worthy research.

### WeChat Channels

Prefer recognizable event, clear consequence, shareable explanation, and compact context that can travel outside a niche community.

### Kuaishou

Prefer direct benefit, plain language, visible proof, and specific result.

### Weibo

Prefer the current phrase, question, number, reaction, and comment-remix language.

### YouTube

Prefer accurate intrigue, short title with important words early, simple readable thumbnail, and immediate delivery on the packaging promise.

## Migration examples

### Example 1: current public question

Hotspot:

`某机器人公司到底值多少钱？`

Do **not** memorize:

`问 InkClawAgent`

Retrieve:

`hotspot_question_product_work + open_question + specific_number`

Then remap product role:

- finance research product -> valuation assumptions + sources;
- sales radar -> companies/buyers/suppliers showing real robotics demand;
- knowledge tool -> organize filings, news, research and debates;
- automation tool -> run the research/approval workflow;
- design tool -> generate an explainer graphic about the question.

Same hook family; different causal role.

### Example 2: “降本增效” workplace meme

Do **not** automatically make a workplace cartoon.

Possible remaps:

- automation product -> delete repeated steps;
- sales product -> stop wasting reps on low-intent leads;
- knowledge product -> reduce search/rework;
- design product -> reduce repetitive resizing/versioning;
- coding product -> eliminate manual boilerplate.

Portable logic:

`not_x_but_y + constraint_deletion + concrete_consequence`

### Example 3: sports comeback

Possible remaps:

- workflow product -> recover a failed project;
- monitoring product -> detect the turning point;
- creative product -> recreate the comeback mechanism in original sports-like grammar;
- sales product -> revive dormant leads.

Portable logic:

`unexpected_reversal + comeback/restoration`

Not: copy the athlete's face or uniform.

## How new learning enters the library

Store a generalized lesson only when it survives the “product swap test”:

> If the promoted brand changes, does the mechanism still make sense after remapping the product role?

If yes, it may belong in the portable library.

If the lesson depends on one mascot, one exact character, one exact title, one product feature, one platform screenshot or one historical layout, it belongs in concrete reference memory or campaign history, not the portable logic layer.

## What the library must never become

- a clickbait phrase dump;
- a static “100 viral hooks” list;
- a replacement for current research;
- an excuse to recycle old visuals;
- a source of unsupported financial/medical/legal claims;
- a guarantee of platform performance.

The taxonomy is a **retrieval prior**. Fresh evidence and product truth remain authoritative.
