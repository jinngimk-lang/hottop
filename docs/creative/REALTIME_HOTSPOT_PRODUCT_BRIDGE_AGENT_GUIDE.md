# Hottop Realtime Hotspot → Product Bridge Agent Guide

> Audience: any agent using this repository to discover current hotspots and generate promotional image/video/social creative for **any** product, brand, service, feature, campaign, idea, or tool.
>
> This document is operational doctrine. It is not a list of yesterday's memes and it is not an InkClawAgent-specific playbook.

## 0. The one-line model

Every fresh creative run should follow this chain:

`fresh user heat → verified source event → active derivative meme/question/action → product truth → functional product role → native creative mechanism → visible consequence → platform-native asset → measured learning`

The transferable unit is the **mechanism**, not the mascot, old headline, old layout, or old product name.

Mandatory recovery order:

Historical Hottop assets teach grammar only. Do **not** silently inherit old cows, old robots, old four-panel layouts, old film grammar, old headlines, old punchlines, `845`-style chat chaos, or any other previous surface treatment unless the **current** hotspot/product bridge independently selects it again.

## 2. Non-negotiable rules

### 2.1 Find user heat, not just official announcements

An official press release proves that something happened. It does **not** prove that users care.

For hotspot discovery, first search for evidence of **active audience attention**:

- live hot-search/ranking pages;
- search suggestions / rising queries;
- community hot-topic lists;
- repeated questions in comments;
- repost/quote/remix behavior;
- derivative memes, screenshots, reaction phrases, repeated numbers or objects;
- platform-native creator responses;
- finance discussion boards / trader hot topics for market content;
- developer/community discussions for technology content.

Then use authoritative/primary sources to verify factual claims.

**Heat evidence and fact evidence are separate evidence classes.** Never substitute one for the other.

### 2.2 Every asset is a fresh run

Before every new image/video generation:

- re-resolve the product;
- re-search live hotspots;
- re-select the bridge;
- re-select the format and medium;
- run the Hottop generation preflight.

Do not assume that the hotspot selected ten minutes ago is still best merely because it is in conversation context.

### 2.3 Product truth before product insertion

Never start with: "How can I put the logo into this trend?"

Start with:

- What real job does the product perform?
- What user pain/tradeoff does it remove?
- What does it do that is visually or narratively consequential?
- What can it **actually** research, execute, organize, create, verify, monitor, compare, route, review, or automate?

If a product capability is uncertain or current, research it before using it in copy.

### 2.4 The product must change the story outcome

Run the **swap test**:

> If I replace the promoted product with an unrelated generic brand, does the scene still work?

If yes, the bridge is weak. Rebuild it.

Strong creative makes the product a functional role such as:

- researcher;
- analyst;
- verifier;
- executor;
- reviewer;
- organizer;
- planner;
- creator;
- monitor;
- scout;
- matcher;
- navigator;
- breaker;
- shortcut;
- antidote;
- route;
- transformation;
- decisive reveal.

### 2.5 Borrow the mechanism, not the skin

Do not copy:

- exact public-figure likenesses for promotional creative;
- exact film frames/posters;
- protected characters;
- proprietary product UI/trade dress;
- copyrighted dialogue/song/footage;
- another creator's composition.

Do borrow, when relevant:

- causal structure;
- relationship structure;
- action verb;
- question pattern;
- escalation rhythm;
- reversal logic;
- visual medium grammar;
- native dialogue rhythm;
- reaction timing.

## 3. What counts as a "real" current hotspot

A usable hotspot is not merely a named event. It has enough **current public attention** to support recognition and enough **derivative language/action** to support a creative bridge.

### 3.1 Minimum evidence

Prefer at least one of these combinations:

- **two independent user-signal sources**, or
- **one live ranking/trend source + one derivative discussion source**, or
- **one very strong platform-native trend source + repeated derivative phrases/questions clearly visible in that platform**.

For factual claims inside the creative, also obtain at least one trustworthy factual/primary source when available.

### 3.2 Freshness

Repository default remains fail-closed:

- research observation should normally be within **6 hours** before generation;
- when a reliable publication timestamp is known, selected hotspot publication should normally be within **7 days**.

Use stricter practical windows where appropriate:

- markets / breaking news / sports result: favor **same day / last 24h**;
- fast internet memes: favor **last 24–48h**;
- entertainment releases / product launches: may remain useful for several days only if active user signals persist.

A seven-day-old story with no current derivative activity is not "hot" merely because it fits the product.

### 3.3 Reject candidates when

Reject or heavily penalize a hotspot if:

- only official/company announcements can be found;
- user discussion is tiny or stale;
- the current conversation has moved to a different derivative meme than the original event;
- recognition depends on copying protected character/likeness assets;
- the product connection requires a paragraph of explanation;
- the only bridge is a pun on the brand name;
- factual uncertainty is high and the creative needs strong factual claims;
- the topic is tragic/high-risk and humor would exploit victims rather than the surrounding system/behavior;
- the topic is financially sensitive and the proposed creative implies a personalized buy/sell recommendation.

## 4. Source model: separate heat from truth

For every candidate maintain two parallel evidence lanes.

### Lane A — user heat evidence

Purpose: prove people are actively interested.

Examples by domain:

| Domain | Useful user-signal sources |
| --- | --- |
| China general | Weibo hot search, Douyin hot list/search, Baidu trending/search, Bilibili popular/search, Kuaishou trends, WeChat/Channels discussion signals when accessible |
| Finance/markets | Eastmoney Guba hot topics, Xueqiu/trader discussions when accessible, Weibo/Baidu finance queries, finance creator discussion, market search trends |
| Tech/AI/developer | GitHub trending/issues/discussions, Hacker News, Reddit, X, Bilibili, Weibo, developer forums, search trends |
| Entertainment/culture | Weibo, Douyin, Bilibili, Xiaohongshu public trends/search, Reddit/X/YouTube depending region |
| Consumer | search suggestions, shopping/community discussions, Xiaohongshu/Douyin/Kuaishou/Reddit reviews, creator reactions |
| Sports | platform hot lists, fan communities, live reaction/search trends |

Do not require every source. Use the strongest sources actually accessible for the target audience/platform.

### Lane B — factual verification

Purpose: prove the event/number/claim is accurate.

Prefer:

1. exchange filing / regulator / court / official record when relevant;
2. company investor relations / official documentation;
3. direct primary source/interview;
4. reputable reporting;
5. community interpretation only as opinion, not fact.

For finance, keep **price/action facts, valuation assumptions, analyst opinion, and promotional creative claims** explicitly separated.

## 5. Live search procedure

### Step 1 — choose target platform and audience first

Before searching, record:

- target platform;
- target country/language;
- audience role;
- campaign goal: reach / brand memory / education / conversion / launch / participation;
- output mode: image / carousel / short video / GIF / poster / other.

The same event can have different derivative memes on different platforms.

### Step 2 — broad candidate scan

Search at least 3–5 relevant domains such as:

- technology / AI;
- finance / markets;
- workplace;
- sports;
- entertainment;
- business / sales;
- creator/design;
- consumer;
- policy/society;
- native internet meme.

Collect roughly 8–20 candidates before locking one if the brief allows.

### Step 3 — search the **user language** around each candidate

Do not stop at the event name. Expand using:

- `为什么`
- `到底`
- `值多少`
- `真的假的`
- `谁来`
- `还能不能`
- `怎么回事`
- `网友`
- `评论区`
- `热评`
- `笑死 / 离谱 / 绷不住 / 破防 / 无语`
- exact repeated number;
- exact repeated object;
- exact action verb;
- reaction phrase;
- comparison (`A vs B`);
- consequence (`涨/跌/省/亏/爆/崩/赢/输/下班/交付`).

For markets add:

- `热议`
- `估值`
- `市值`
- `泡沫`
- `财报`
- `IPO`
- `涨停/跌停`
- `主线`
- `轮动`
- `谁受益`
- `风险`
- `预期差`

The goal is to discover the **active public question or derivative meme**, not to manufacture one.

### Step 4 — extract the derivative signal

For each candidate write the shortest real signal users recognize:

- repeated question;
- repeated one-liner;
- decisive number;
- object/prop;
- action verb;
- relationship structure;
- blame/reaction phrase;
- screenshot/interface motif;
- visual symbol;
- recurring before/after comparison.

Example abstraction:

`source event: hot robotics company valuation debate`

`derivative signal: “到底值多少钱？”`

The transferable creative entry is the **question mechanism**, not the company name.

### Step 5 — verify the event separately

Verify names, dates, prices, counts, product facts, filing status, sports result, release state, etc.

Never use derivative meme language as proof that the underlying claim is true.

## 6. Hotspot candidate scoring

Before product mapping, score candidate heat quality out of 100.

| Dimension | Weight | Question |
| --- | ---: | --- |
| Freshness | 20 | Is the signal fresh now, not merely historically famous? |
| User-signal strength | 25 | Is there ranking/search/comment/repost evidence of real attention? |
| Derivative density | 15 | Are people repeating a question/number/action/reaction that can be recognized quickly? |
| Recognition speed | 10 | Can the audience understand the reference in ~1 second? |
| Product bridge potential | 20 | Does the event imply real work the current product can perform? |
| Safety/rights feasibility | 10 | Can we use the mechanism without unsafe claims or protected-surface copying? |

Suggested threshold:

- `80–100`: strong candidate;
- `70–79`: usable if product fit is unusually strong;
- `<70`: normally reject and keep searching.

This is a project heuristic, not a universal law. Actual account performance can tune it later.

## 7. Resolve the current product from zero

Every time the promoted product changes, discard prior brand assumptions and rebuild this product card:

```yaml
product:
  name: ""
  category: ""
  target_user: ""
  job_to_be_done: ""
  real_capabilities: []
  differentiators: []
  pains_removed: []
  visible_outputs: []
  emotional_payoff: []
  category_default: ""
  claims_we_can_prove: []
  claims_we_must_not_make: []
```

Do not copy the previous product's role merely because the hotspot is similar.

One hotspot question can map differently:

- research product → gather sources / compare assumptions / produce analysis;
- finance data product → retrieve market data / scenario calculations;
- sales intelligence product → find buyers / sellers / demand signals;
- knowledge product → organize evidence / retrieve context;
- automation product → execute the workflow;
- coding product → build/test/fix the implied technical task;
- creative product → turn the event into finished media;
- collaboration product → coordinate roles/handoffs/revisions;
- monitoring product → watch for changes and alert;
- design product → produce a visual artifact from the same public signal.

**Same hotspot ≠ same product role.**

## 8. Bridge search: make product and hotspot mutually necessary

Search for bridges in this order.

### 8.1 Question → product does the real work

Use when users are asking:

- "到底怎么回事？"
- "值多少？"
- "为什么？"
- "谁受益？"
- "还能不能？"

Mechanism:

`public question → required research/work → product performs that work → visible artifact/decision context`

Do not jump straight to a definitive answer if the product merely helps research.

### 8.2 Hotspot action → product takes analogous action

Use the current event's verb:

- 开拍;
- 上场;
- 开工;
- 审核;
- 交付;
- 抢跑;
- 反转;
- 追踪;
- 复盘;
- 上线.

Mechanism:

`hotspot is doing ACTION → current product can truthfully do analogous ACTION on user's work`

### 8.3 Number/consequence → product explains or changes the consequence

Use when a concrete number is the recognition hook:

- money;
- market cap;
- version count;
- hours;
- error count;
- latency;
- score;
- users;
- sales;
- win/loss result.

The number should be real if stated as fact.

### 8.4 Pain → physical prop → product removes/transforms it

Turn abstract pain into:

- mountain;
- queue;
- maze;
- wall;
- lock;
- flood;
- trash pile;
- endless stack;
- boss fight;
- broken relay race.

Then make the product perform a real functional job on the prop.

### 8.5 Relationship → product takes a role

Map the hotspot relationship:

- coach/player;
- boss/employee;
- director/crew;
- analyst/trader;
- doctor/patient only with care and no medical overclaim;
- detective/evidence;
- teacher/student;
- judge/reviewer;
- scout/team;
- pit crew/driver.

Use an original archetype, not a protected likeness/character.

### 8.6 Constraint deletion

Ask:

- Why must users still do this step?
- Can the current product remove the step entirely?

Better:

`not “do old step faster” → “old step disappears”`

Only use if the product genuinely deletes/reduces that constraint.

## 10. Generate at least three concept routes internally

Before choosing one, explore at least:

1. **pain/consequence route** — recognizable pain or current consequence;
2. **bridge/action route** — product performs an action native to the hotspot;
3. **reframe/constraint-deletion route** — change the assumption rather than decorate it.

Optional fourth route:

4. **public question → product work** — especially strong for finance, AI, tech, business, research, and current-event topics.

Rank concepts using the portable library score:

- hotspot-native fit: 25;
- product-role fit: 25;
- instant comprehension: 15;
- surprise/reframe: 15;
- platform fit: 10;
- ownability: 10.

Reject a high-scoring concept if it fails truth, safety, copyright, likeness, or financial guardrails.

## 11. Hook writing: hotspot first, product consequence second

Cold audiences do not care about the product name yet.

Prefer hooks such as:

- current question;
- current number;
- current consequence;
- short contradiction;
- role reversal;
- native comment rhythm;
- concise `not X, but Y` reframe.

Avoid by default:

- "Introducing [PRODUCT]";
- feature lists in the headline;
- newsroom-style long summaries;
- generic `AI efficiency tool` language;
- internal labels such as `热点梗图`, `热搜TOP1`, `创意方向A` on the audience-facing asset.

Audience decoding order should normally be:

`recognize hotspot → understand mapping → see product change outcome → get punchline → notice attribution`

### Hook compression check

Before finalizing the title ask:

> Can I remove half the words and preserve the recognizable question/number/action/consequence?

If yes, compress it.

## 12. Format selection

Do not default to four panels.

Choose the smallest format that makes the mechanism land.

### Single visual

Use when one metaphor/reversal is instantly legible.

Good for:

- one question;
- one action;
- one strong prop;
- one before/after contrast;
- one role reversal.

### Two-part / split image

Use when the core is:

- before vs after;
- old assumption vs deleted constraint;
- human does everything vs product takes the real work.

### Four-panel

Use only when the joke genuinely needs:

`setup → escalation → reversal → punchline`

Do not use four panels merely because Hottop used them in earlier examples.

### Carousel

Use when attention and explanation need separate frames.

Frame 1 earns attention. Later frames add evidence/product clarity.

### Short video

Use when recognition depends on:

- timing;
- action;
- dialogue;
- reaction;
- transformation;
- sound;
- physical escalation.

A pan/zoom slideshow is not successful narrative video.

---

## 13. Visual grammar must match the hotspot

Examples:

- live sports → original documentary/sports-cinematic energy;
- stock-market debate → trader/research desk / data-documentary grammar, not generic neon AI wallpaper;
- film/culture → original cinematic grammar, not exact protected frame;
- internet-native crude meme → intentionally native roughness when roughness is part of recognition;
- software/AI → contemporary working environment, visible artifacts/results, not feature-card overload;
- consumer → product/ritual/usage environment;
- creator trend → social-native or studio production grammar.

**Match the medium, not protected assets.**

## 14. Fresh prompt construction: prevent stale-template contamination

Every final generation prompt should begin conceptually from a clean slate.

Use this structure:

```text
CURRENT RUN RESET
Use only the current brief and current hotspot mechanism.
Do not reuse historical Hottop characters, mascots, numbers, layouts, scenes,
punchlines, feature cards, or prior product visual shells unless explicitly listed below.

PROMOTED SUBJECT
- product:
- true job:
- capability used in this story:

CURRENT HOTSPOT
- source event:
- active derivative question/phrase/action:
- recognition cue:

BRIDGE
- mechanism:
- product role:
- how product changes the outcome:

SCENE / MEDIUM
- native visual grammar:
- characters/archetypes:
- environment:
- decisive action:
- final visual consequence:

COPY
- headline:
- dialogue/caption:
- light attribution:

MUST NOT
- stale historical template elements
- unverified claims
- public-figure likeness recreation
- protected character/frame/UI copying
- feature-list poster treatment unless explicitly selected
```

If the generator visibly inherits an old visual shell despite the reset:

1. **reject the artifact**;
2. do not rationalize it as acceptable reuse;
3. restart from a neutral prompt/reference or isolated fresh canvas;
4. only proceed when the current-run semantics are visually dominant.

This rule exists because generator/context contamination can produce visually polished but semantically stale output.

## 15. Mobile-first copy discipline

A social creative is not a presentation slide.

Prefer:

- one main hook;
- one decisive secondary line or speech bubble;
- one visible product consequence;
- small/light brand attribution.

Avoid:

- dense feature grids;
- tiny explanatory paragraphs;
- six competing headlines;
- internal research dashboards on the final creative;
- URLs/QR codes/CTA blocks unless the brief is explicitly conversion-first.

If the image only works after zooming in, it fails instant comprehension.

## 16. Finance / market hotspot rules

Markets can produce excellent live questions because users naturally ask:

- "值多少钱？"
- "为什么涨/跌？"
- "泡沫还是机会？"
- "主线是谁？"
- "谁受益？"
- "财报说明什么？"

Use the **research process** as the product bridge when possible.

Safe pattern:

`people are debating valuation → product gathers evidence / compares assumptions / builds scenarios → human still decides`

Do not:

- fabricate target prices;
- claim guaranteed upside/downside;
- disguise promotional copy as personalized investment advice;
- state a disputed valuation as fact;
- use old prices/current market-cap numbers without fresh data;
- treat community sentiment as verified financial fact.

When numbers appear, capture source and timestamp.

For a finance creative, the product often works best as:

- researcher;
- data retriever;
- scenario builder;
- verifier;
- summarizer;
- monitor;
- comparison engine.

## 17. Real people / celebrities / athletes / founders

A public figure may be the current hotspot, but promotional creative should normally use:

- event mechanism;
- role archetype;
- sports/cinematic grammar;
- anonymous/original character;
- symbolic prop/action;

rather than reproducing the real person's face.

If the event is the recognition hook, keep factual attribution in copy while using an original visual archetype when appropriate.

---

## 18. Sensitive/tragedy hotspot handling

When a real event involves injury, death, harassment, labor disputes, victims, disasters, or other sensitive harm:

- do not make the victim the joke;
- if using the topic, joke about the **system, workflow, absurd condition, or broader behavior** only when appropriate;
- avoid false quotes/reenactments;
- favor informative/reframing creative over shock exploitation;
- reject the hotspot if the product bridge depends on trivializing harm.

## 20. Hard review before accepting generated output

A visually attractive artifact can still be a creative failure.

Check in this order:

1. **Currentness** — is this actually today's/current hotspot mechanism?
2. **Instant comprehension** — can target users decode it immediately?
3. **Natural linkage** — is the product inside the causal chain?
4. **Product truth** — does the product really do what the story claims?
5. **Outcome change** — can viewers see what changed because of the product?
6. **Surprise/reframe** — is there a reason to stop scrolling?
7. **Native grammar** — does it feel like the source platform/hotspot medium?
8. **Originality** — is it a fresh execution rather than historical Hottop surface reuse?
9. **Copy legibility** — readable at phone size?
10. **Evidence safety** — facts, finance, likeness, copyright, trademark, sensitive-event checks pass?

Fail closed if any hard requirement fails.

## 21. Platform routing priors

These are priors, not laws. Real account performance overrides generic guidance when comparable data exists.

### Douyin / TikTok

- hook immediately;
- concrete conflict/question/outcome;
- vertical/native framing;
- brand-name-first cold opens often underperform unless the brand itself is the trend;
- show outcome/action rather than feature list.

### Xiaohongshu

- utility / experience / comparison / save-worthy framing;
- first image should answer "why should I save/read this?";
- product launch announcement alone is usually weaker than a concrete problem/result.

### WeChat Channels

- event relevance + clear consequence + shareable context;
- simple story and social proof work well when truthful.

### Kuaishou

- direct benefit;
- plain language;
- visible proof;
- low abstraction.

### Weibo

- current phrase/question/number/reaction;
- derivative meme and public conversation first;
- speed matters.

### YouTube

- accurate intrigue;
- thumbnail/title promise must be delivered immediately;
- avoid misleading curiosity gaps.

## 22. Performance learning loop

After publishing, do not judge only by raw views.

Record when available:

- impressions / plays;
- 2-second / 3-second hold or skip;
- completion;
- reading expansion;
- average images viewed;
- likes;
- comments;
- shares;
- saves;
- follows;
- traffic source split (recommendation/search/profile/following);
- search keywords;
- post age at measurement.

Interpretation rules:

- compare posts at similar age when possible;
- separate weak distribution from weak retention;
- high recommendation traffic + weak interaction means the hook may work but conversation value is weak;
- high reading/save behavior can be more meaningful than raw reach for utility platforms;
- a fresh post with fewer views is not automatically worse than an older post;
- one account's observation is evidence, not a universal platform law.

### Persist learning at the right level

After user feedback/performance:

- concrete case → `integrations/creative-reference-library.yml`;
- genuinely product-independent lesson → `integrations/portable-creative-logic-library.yml`;
- research/source methodology improvement → this guide or research docs;
- do not turn one successful visual shell into a default template.

## 23. Anti-patterns to actively challenge

Reject these common failures:

### Newsroom summary + logo

Bad:

`long summary of today's news + product logo at bottom`

Why: product is decorative.

### Trend costume

Bad:

`protected-looking hot character wearing product logo`

Why: borrows skin, not mechanism.

### Brand-first hook

Bad:

`[PRODUCT] is an amazing AI tool...`

Why: cold audience has no reason to care.

### Feature-grid ending

Bad:

`meme setup → huge UI card with 8 product features`

Why: breaks entertainment/scene immersion.

### Yesterday's successful template

Bad:

`same mascot + same four panels + new hotspot nouns`

Why: historical reference has become template contamination.

### Official-only "hotspot"

Bad:

`company posted announcement → therefore trend`

Why: fact evidence is not heat evidence.

### Fake certainty

Bad:

`community asks “what is it worth?” → creative gives invented target price`

Why: turns an open question into unsupported claim.

## 24. Minimal operating recipe for another agent

If context is tight, execute this minimal loop:

1. Read `PROJECT.md`, `STATUS.md`, this guide, portable-logic skill/library.
2. Resolve current product truth and product job.
3. Search live user heat across at least 2 useful user-signal sources.
4. Verify the source event separately.
5. Extract the active derivative question/number/action/reaction.
6. Score 3–5 candidates; select strongest current candidate.
7. Retrieve 3–7 portable logic families.
8. Map product to a non-replaceable functional role.
9. Explore 3 fresh concepts; choose smallest suitable format.
10. Write hotspot-native hook first; product consequence second; light attribution last.
11. Build clean generation prompt with historical-template reset.
12. Run Hottop generation preflight.
13. Generate.
14. Hard-review currentness, bridge, truth, legibility, rights, finance/safety.
15. Publish/package only after passing review.
16. Record user feedback/platform performance back into the correct memory layer.

## 25. Core doctrine
