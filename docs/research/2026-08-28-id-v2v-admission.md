# ID-V2V continuity admission review

Date: 2026-08-28
Status: **research / operator benchmark candidate only**

## Why it matters

ID-V2V is a SIGGRAPH Asia 2026 video-to-video restylization system designed to preserve a source performance while changing scene/style from one or more stylized keyframes. Its useful Hottop lesson is narrower than ordinary reference-conditioned I2V: when a rights-safe source performance already exists, identity fidelity and motion/performance fidelity can be jointly constrained instead of asking a generator to invent both from a still reference.

This makes it relevant to Production v0.2's canonical rule that identity fidelity and motion fidelity are separate evidence dimensions. It does **not** replace Hottop's current LightX2V/Wan2.2 still-reference benchmark path because ID-V2V requires a source video.

The code repository and checkpoint metadata are permissive, but this does not automatically clear the source video's rights, stylized keyframe rights, SAM3 terms/access, Wan base assets, output/publication rights, or any separately fetched preprocessing model.

## Published runtime / provisioning boundary

The upstream README documents:

- Python 3.10;
- PyTorch 2.6 + CUDA 11.8;
- `xfuser` and FlashAttention;
- tested hardware: **8 × A100 80 GB**;
- a single-GPU CPU-offload mode that is documented as slower but still requires an operator GPU runtime;
- Hugging Face authentication for gated SAM3 access;
- a checkpoint installer that fetches ID-V2V + SAM3 + Wan2.1 T5/VAE/tokenizer/CLIP, approximately **96 GB** for the default path;
- an optional normal/depth path that downloads additional DAViD + DepthAnything-V2 assets;
- first-run behavior that auto-installs FFmpeg.

These behaviors are incompatible with normal unattended Hottop execution. Hottop must not invoke the upstream setup/download scripts, perform HF login, auto-install FFmpeg, or download checkpoints/models during CI or normal `video-run`.

## Identity / motion value

The default flow takes:

1. a rights-safe **source video** whose motion/performance is already known;
2. a stylized first frame and optional additional keyframes;
3. a text prompt;
4. a per-frame control signal derived from the source video (foreground-on-gray pixels using SAM3 for the default route).

The generated video is intended to preserve identity, expression, gaze and body movement from the source while restyling scene/lighting/background. Longer videos are generated clip-by-clip with overlap conditioning, and optional keyframes can anchor specific frames.

For Hottop this is best understood as a possible future **motion-preserving restylization recovery route**, not as a generic T2V/I2V generator. A successful benchmark would need to show that the restyled output preserves both subject identity and the original source motion/performance under Hottop's own output-side evaluator.

## Admission decision

Do **not** add an executable production route now.

Reasons:

- physical operator runtime is unprobed;
- the documented setup is extremely heavy (8×A100-tested, ~96 GB default assets);
- upstream scripts include behaviors Hottop explicitly forbids in unattended mode (model downloads, gated-login setup, first-run FFmpeg install);
- the method requires a source performance video, so it does not fill the same still-reference gap as LightX2V/Wan2.2;
- source/reference/keyframe/output rights remain execution-time gates even though source and checkpoint metadata are Apache-2.0.

Classification: `research / operator benchmark candidate`, `integration_ready=false`, `runtime_status=unprobed`.

## Re-admission gate

Re-evaluate only when an operator has already provisioned the exact source/checkpoint/runtime stack without Hottop auto-install/download and supplies rights-safe benchmark inputs:

- a source video owned/generated by the operator or otherwise rights-cleared;
- stylized keyframe(s) with matching rights provenance;
- exact local source revision and checkpoint hashes/revisions;
- independently reviewed SAM3/base/preprocessor terms where used.

Benchmark against the same source sequence with:

- identity fidelity evidence;
- motion/performance fidelity evidence against the original source;
- keyframe/style adherence;
- motion/non-degeneracy and final-media gates;
- byte-bound artifact provenance;
- generator/evaluator source revisions.

No identity or motion-preservation claim should enter Hottop production based on upstream demo language alone.

## Durable takeaway

ID-V2V strengthens an existing Hottop direction rather than changing it: when a rights-safe performance already exists, a motion-preserving video-to-video route can be a better recovery strategy than regenerating motion from a still. This remains an optional future route and never weakens the guaranteed zero-cost software3d baseline or the current operator-controlled provisioning policy.
